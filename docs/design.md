# Design notes

## Why additive synthesis

The constraint is "sine waves only". That rules out sampled speech, noise generators and conventional filter-feedback vocoders. What remains is additive synthesis: build every output sample as a sum of sine functions.

A voiced sound uses a harmonic series. If the fundamental is `F0`, the partials are `F0, 2F0, 3F0, ...`. A real glottal pulse has energy that falls with frequency, so partial `n` starts with weight `1/n`. The vocal tract then emphasises some frequencies and suppresses others. Formant synthesis models that emphasis as four resonances:

```
response(f) = Σ band[k].amplitude / (1 + ((f - band[k].frequency) / band[k].bandwidth)²)
```

Each phoneme supplies the four bands. `ee` has a low F1 (~270 Hz) and a very high F2 (~2290 Hz); `oo` has both low (~300 and ~870 Hz). That contrast is what makes vowels distinguishable.

Unvoiced sounds need high-frequency energy but no pitch. Instead of random noise, the engine sums twelve sine partials with fixed pseudo-random frequencies and phases. The phases are generated by a deterministic LCG, so renders are reproducible. The same four-band response shapes those partials, which gives `s`, `sh` and `f` different spectra.

## Smoothing

Three things are interpolated or enveloped to remove discontinuities:

1. **Formant targets** — a 35 ms crossfade from the previous phoneme's bands to the current one.
2. **Voicing** — the voiced/unvoiced mix crossfades over the same window.
3. **Diphthongs** — `ay`, `oy`, `ow`, `oi` and `eye` store a second band set and glide from it across the phoneme, rather than holding one static vowel.
4. **Amplitude** — per-phoneme attack and release, with shorter values for plosives.

The harmonic phase is a single accumulator across the whole utterance, so pitch changes do not reset the waveform.

## Intonation

Pitch drifts down slightly across a phrase, as it does in natural speech. A `?` that closes the utterance raises the final half-second of pitch; a question mark earlier in the phrase does not affect a later statement. Vibrato is applied in cents, so it scales with the chosen fundamental.

IPA input adds per-segment `amplitude`, `pitchStart` and `pitchEnd`. Primary and secondary stress change amplitude, duration and F0 slightly; vowel length scales duration; tone letters and tone diacritics set a linear F0 contour across the segment. The global rise symbol (`↗`, X-SAMPA `<R>`) applies the same final-half rise as `?` whether it precedes or follows the segment.

## Data model

`Voice` holds synthesis parameters only. Presets are functions that return a filled struct; there is no inheritance and no global state. `Phoneme` holds a name, a kind, four bands, a duration, a voicing flag and optional prosody (`amplitude`, `pitchStart`, `pitchEnd`). Diphthongs additionally carry a second band set and a `hasEndBands` flag. Both are plain data, so a caller can build their own.

IPA and X-SAMPA are parallel *front ends*, not a second synthesis path. `src/ipa.cpp` decodes UTF-8, maps each base letter to articulatory features (manner, place, height, backness, rounding), applies diacritics and suprasegmentals, then emits the same `Phoneme` struct used by the English lexicon. Vowel height maps inversely to F1; frontness maps to F2; rounding lowers F2. Consonants take four place-specific resonance centres and a manner-specific amplitude profile. This keeps the "formant data in the phoneme table" rule: the synthesiser still only sees four bands.

## Languages

Language coverage belongs in the front end. The synthesiser consumes a `Phoneme` sequence and knows nothing about orthography, so a new language changes how text becomes phonemes, not how sound is produced.

The layers are:

1. **Text normalisation and tokenisation** — UTF-8 is decoded explicitly, so accented letters and non-ASCII punctuation never depend on the process locale.
2. **G2P module** — a language tag selects rules, an optional lexicon and a stress model. Each module returns the same `Phoneme` struct used by the IPA front end.
3. **Shared inventory and prosody** — vowel formants come from articulatory height/backness/rounding; consonants from place and manner. Stress, length and intonation are data on the segment.
4. **Language-independent synthesis** — one additive engine renders every language.

This mirrors the split used by eSpeak NG (language rules and phoneme tables feeding a shared synthesiser), MaryTTS (a language-specific `Phonemiser` in front of a shared voice) and Rhasspy's IPA-first inventory. Keeping the inventory IPA-based also means a language module can be tested by comparing phoneme names, without rendering audio.

English uses a small lexicon plus letter rules. Spanish uses Castilian rules: `c`/`z` become /θ/, `g` before a front vowel becomes /x/, `gu`/`qu` keep a silent `u`, `b` and `v` merge, `ll` becomes /ʝ/ and `ñ` /ɲ/. Word-initial and post-nasal or post-lateral `r` is a trill while intervocalic `r` is a tap, and `i`/`u` become glides inside diphthongs. Stress comes from a written acute accent, otherwise from the penultimate/final rule. Inverted `¿`/`¡` are separators; a closing `?` still marks the utterance-final rise.

Adding another built-in language means implementing a tokeniser and a G2P module, adding a tag to the registry and adding test vectors. No synthesis code changes. Known limits: no allophonic rules ([β ð ɣ]), no dialect selection (seseo/distinción), no automatic language detection, and Spanish has no lexicon yet.

A language definition file extends this without C++: it supplies grapheme routes, a word lexicon, an optional inventory, per-phoneme realization overrides and ordered context-sensitive rewrite rules for romanisation and allophony, then feeds the same IPA parser and synthesizer. The line-oriented format, rule matching and precedence are in [docs/language-files.md](language-files.md). Phonotactic generation remains separate work.

## Exact timing

Because durations are assigned to phonemes before synthesis, timing is not a post-hoc analysis of the waveform. `src/schedule.cpp` owns the single cumulative scheduler that rounds `duration * sampleRate / rate` at each phoneme boundary; `Synthesizer::render()` and `planTiming()` both consume it, so emitted `startSample`/`endSample` values describe the exact buffer that was rendered, including fast rates and zero-length segments. Word units group phonemes around `|` gaps, fold pauses into the preceding word, and use source-text labels when available. Visemes are a separate data table keyed by phoneme name with a `PhonemeKind` fallback; both are pure transforms of the plan. This keeps the usual rule that data lives in tables and nothing mutates global state. See [docs/timing.md](timing.md) for formats and the public API.

## Possible extensions

- More language front ends (French, German, Italian) behind the same registry.
- Language detection and per-span tags for mixed-language text.
- A larger English lexicon or an external pronunciation file.
- Stereo and streaming output.
- Real-time playback adapters (Core Audio, PipeWire, SDL).
- Per-phoneme overrides in a voice file.

The engine deliberately does not own an audio device. It returns `std::vector<float>` so callers decide what to do with it.
